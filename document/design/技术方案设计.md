## 一、技术方案设计

### 1. 整体架构

- **移动端**：uni-app（编译为iOS/Android App，以及可能的H5/小程序备用）
- **服务端**：Java Spring Boot 单应用，分层架构（Controller - Service - Mapper）
- **数据库**：MySQL 8.0（主库），读写操作直接命中，无分库分表
- **缓存**：Redis 7.x，用于会话、汇率、高频配置、预算计算中间结果
- **文件存储**：本地存储 + 可选阿里云OSS（用户记账图片、小票），前端直传，后端只存URL
- **消息推送**：极光推送/个推（UniPush）

### 2. 接口规范

- 全部采用 RESTful API，JSON 格式交互
- 版本前缀 `/api/v1/`
- 认证：JWT（Access Token 2小时过期 + Refresh Token 7天），登录后所有请求头携带 `Authorization: Bearer <token>`
- 多账本隔离：所有数据接口通过请求参数或路径携带 `bookId`，后端结合当前用户鉴权，确保账本数据隔离
- 离线记账：本地优先记录，后台定时任务每 30 分钟自动同步。同步流程：① 逐条推送本地待同步数据至服务端 → ② 推送成功后清除对应本地记录 → ③ 拉取服务端最新数据与本地剩余缓存合并展示。冲突解决策略为“服务端为准”（本地数据推送成功后即清除，避免冲突）

### 3. 离线记账与同步机制

**核心原则**：本地优先、异步同步、拉取合并。

#### 3.1 记账流程

```
用户记账 → 存入本地 Storage（sync_status=pending）→ 立即展示 → 返回
```

记账操作不等待网络请求，保证离线可用、操作瞬时响应。

#### 3.2 后台同步任务

每 30 分钟自动执行一个同步周期：

1. **推送阶段**：逐条读取本地 `sync_status=pending` 的记录，调用 `POST /api/v1/transactions` 上传
2. **清除阶段**：推送成功的记录从本地 Storage 中删除（不保留，避免冲突）
3. **拉取阶段**：调用 `GET /api/v1/transactions` 获取服务端最新数据，写入本地 Storage（`sync_status=synced`）
4. **合并展示**：本地 pending 数据 + 服务端 synced 数据按日期合并排序展示

#### 3.3 触发时机

| 触发条件 | 行为 |
|---------|------|
| 应用启动（onShow） | 拉取服务端数据合并展示，启动 30 分钟定时器 |
| 网络恢复（从离线到在线） | 立即执行一次完整同步周期 |
| 用户下拉刷新 | 执行完整同步周期 |
| 定时器到期 | 后台静默执行同步周期（不显示 loading，失败不弹 toast） |

#### 3.4 数据存储结构

本地 Storage key: `local_transactions`，存储 `LocalTransaction[]` 数组。

```
LocalTransaction {
  id: number;           // 本地 ID（负数，避免与服务端 ID 冲突）
  server_id?: number;   // 服务端 ID（同步成功后回填）
  sync_status: "pending" | "synced" | "failed";
  // ... 其他业务字段
}
```

#### 3.5 冲突处理

- 本地数据推送成功后立即清除，以服务端数据为唯一权威源
- 推送失败的数据保留在本地（`sync_status=failed`），下次同步周期重试
- 同一笔记录在服务端已存在时（server_id 匹配），跳过重复推送

#### 3.6 静默同步

后台定时同步使用轻量请求（不显示 loading、失败不弹 toast），避免干扰用户操作。仅在下拉刷新时显示加载状态。

### 4. 缓存策略

- **用户会话**：JWT 黑名单存 Redis（退出登录时添加，TTL为Token有效期）
- **实时汇率**：定时任务从外部API抓取，存入 Redis 并设置1小时过期，多币种换算时读取
- **预算消耗进度**：当记一笔账后，同步更新 Redis 中当月该预算的已用金额（Incrby），报表查询时若缓存存在直接返回，否则从DB汇总并回填
- **智能分类推荐模型**：基于用户最近记账习惯（分类-金额-时段）的简单权重，缓存于 Redis Hash，记账时快速给出推荐分类ID

### 4. 安全方案

- 传输层全站 HTTPS
- 密码：BCrypt 加密存储，用户自设的“独立数据密码”用于云同步密钥派生，服务端不存
- 金额字段全部以 `INT` 存储分（￠），避免浮点
- 防注入：MyBatis 参数化查询，输入清洗
- 敏感操作日志脱敏

### 5. 第三方服务集成

- **OCR识别**：接入百度智能云 OCR，拍照上传小票后异步返回商户、金额，前端填入
- **语音识别**：uni-app 调起系统语音，将音频流或文本传至后端，后端调用讯飞语音转写，解析出金额+分类关键词返回

### 索引设计

- `transaction` 表对 `(book_id, trans_time)` 建立联合索引，对 `account_id` 建单独索引。
- `budget` 表对 `(book_id, period_type, start_date)` 建立索引。
- 所有外键列建索引。
- `account_book_member` 对 `(book_id, user_id)` 建唯一索引。

### 缓存与DB交互补充

- 账户余额不存储具体字段，通过 sum(transactions) 实时计算或周期性固化到账户的 `balance` 缓存，但表内不存余额列，避免不一致。但为了性能，可在 Redis 中存每账户的当前余额，每次记账后通过事务更新 Redis。数据库仅作为流水记录。
- 预算已用金额可使用 Redis 的 ZSET 或 Hash 按月存储，定时任务每日将 Redis 数据刷新到一张 `budget_usage` 表（作为历史快照），避免 Redis 宕机丢失。
