## 代码问题清单

### 后端

1. **Controller 路径偏离计划**: 计划要求 `/api/v1/auth/*`，当前是 `/user/*`。前端 api/example.ts 调 `/api/user/login`，common.ts 也调 `/api/user/login`——与后端一致但都不符合计划规范。
2. **JWT 密钥不持久**: `JwtUtils` 用 `Keys.secretKeyFor()` 每次启动随机生成密钥。重启后所有已发 token 全部失效，必须改为固定密钥或从配置读取。
3. **Spring Security 未配置**: pom.xml 引入了 starter-security，但无 SecurityConfig 配置类。默认行为会拦截所有请求并弹出登录表单，可能阻塞 API 测试。
4. **H2 数据库表不全**: 计划中 user/account_book/account/category/transaction 五张表，仅 user 通过 JPA entity 自动建表。其余 entity 类全部缺失。
5. **注册无重复校验**: `UserService.register()` 未检查 username 是否已存在，直接 insert 会抛 DataIntegrityViolationException。
6. **后端返回格式不统一**: AuthController 返回 `{code, message, token}` 嵌套在 Map 中，无统一的 Result 包装类。前端 request.ts 期望 `{code: 0|200, data: ..., message: ...}`。
7. **无全局异常处理**: 缺少 @ControllerAdvice，异常会暴露 Spring Boot 默认 JSON 结构给前端。
8. **测试仅空壳**: `BackEndApplicationTests` 只测 contextLoads，无任何业务测试。

### 前端

1. **API 层重复**: `api/example.ts` 和 `api/common.ts` 都定义了 login/getUserInfo/updateUserInfo，类型定义也重复。
2. **登录后无跳转**: `pages/login/index.vue` 的 handleLogin 取到 token 后未存储、未跳转主页。
3. **VITE_API_BASE_URL 未配置**: request.ts 从 import.meta.env 读 baseURL，但项目无 `.env` 文件。
4. **首页为模板占位**: `pages/index/index.vue` 仍是 uni-app 默认模板，无记账功能代码。
5. **pages.json 首页 title 是 "uni-app"**: 应改为记账相关标题。
