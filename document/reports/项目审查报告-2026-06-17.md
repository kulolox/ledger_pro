## 一、严重问题 (Critical) — 共 7 项

### C1. 统计接口缺少账本归属权校验 (IDOR) — 后端

**文件:** `StatisticsServiceImpl.java:18`  
**影响:** 任意用户可通过猜测/枚举 bookId 获取其他用户的完整财务统计数据（支出总额、收入总额、分类明细）

`monthly()` 方法直接按 `book_id` 查询交易，缺少与 `TransactionServiceImpl.validateBookOwnership()` 同等的归属权校验。所有其他交易接口均有此校验，唯独统计接口遗漏。

---

### C2. JWT 类型校验逻辑有缺陷 — 后端

**文件:** `JwtUtils.java:55-71`  
**影响:** 无 `type` claim 的 token 可同时通过 `validateToken` 和 `validateRefreshToken` 两个校验，破坏了 access/refresh token 的职责分离

```java
// validateToken: !"refresh".equals(null) → true (通过)
// validateRefreshToken: type == null → true (通过)
```

---

### C3. 本地 ID 生成策略导致与服务器 ID 冲突 — 前端

**文件:** `transactionStore.ts:32`  
**影响:** 完整同步周期后 `nextLocalId` 变为正数，与服务器 ID 碰撞导致数据静默丢失

同步成功后本地 pending 数据（负 ID）被移除，pull 回来的数据（正 ID）重新写入。下次启动时 `nextLocalId = Math.min(...正数) - 1` 计算出正数，新建交易的本地临时 ID 会与服务器后续分配的 ID 冲突。

---

### C4. pushPending 成功后 pullFromServer 失败导致数据丢失 — 前端

**文件:** `sync.ts:108-110, 217`  
**影响:** 推送到服务器成功→本地删除→拉取失败 = 交易在本地永久消失

`pushPending` 成功后无条件 `setLocalTransactions(remaining)` 删除已同步项。若后续 `pullFromServer` 因网络错误失败，这些数据只在服务器存在，本地 UI 不可见，用户以为数据丢失。

---

### C5. CSV 导入金额解析算法根本性错误 — 前端

**文件:** `import-export/index.vue:242-251`  
**影响:** CSV 导入的金额数据大概率被错误放大 100 倍

```typescript
if (n > 100000) return n;        // 假定大数是"分"
return Math.round(n * 100);      // 假定小数是"元"
```

对于 `"1200"`（本意 1200 分 = 12 元），`parseInt` 得 1200，不大于 100000，乘以 100 得 120000 分 = 1200 元——100 倍错误。分/元判断用任意阈值不可靠。

---

### C6. 前端全局 `uni` 类型声明为 `any` — 前端

**文件:** `types/uni.d.ts:1-7`  
**影响:** 整个 uni-app API 调用链失去类型检查

应使用官方 `@dcloudio/types` 包替代手写的 `declare const uni: any`。

---

### C7. 硬编码默认 JWT 密钥 — 后端

**文件:** `JwtUtils.java:18`  
**影响:** 若 `JWT_SECRET` 环境变量未设置，使用源码中硬编码的 `"ledger-pro-default-secret-key-2026"`，任何有源码访问权限的人可伪造 JWT

## 二、高危问题 (High) — 共 14 项

### H1. 导入金额解析存在整数溢出 — 后端

**文件:** `TransactionServiceImpl.java:266-273`  
**影响:** 导入 ≥ 21,474,836.48 元的金额时 `(int) Math.round(... * 100)` 溢出为负数，数据库写入负数金额

---

### H2. 交易金额缺少正数校验 — 后端

**文件:** `TransactionRequest.java:11`  
**影响:** 可通过 API 创建负金额交易，扰乱统计数据

`amount` 字段仅有 `@NotNull`，缺少 `@Positive` 或 `@Min(0)` 约束。

---

### H3. 退出登录不使 access token 失效 — 后端

**文件:** `JwtAuthFilter.java:26-34`  
**影响:** 退出登录后 access token 仍有效长达 24 小时，无法撤销被窃 token

JWT 认证过滤器仅校验签名和过期，不检查黑名单。`logout()` 仅将 refresh token 加入黑名单。

---

### H4. 缓存驱逐仅处理当月 — 后端

**文件:** `TransactionServiceImpl.java:82-87`  
**影响:** 创建/修改非当月交易后，对应月份的缓存不更新，返回过期数据

```java
String currentMonth = java.time.YearMonth.now().toString();
// 如补记上月交易，上月的 transactions 缓存不会驱逐
```

---

### H5. parseType 存在复制粘贴错误 — 后端

**文件:** `TransactionServiceImpl.java:257-258`  
**影响:** 代码意图是同时匹配中英文，但实际比较了两次相同文本

```java
if (trimmed.equals("收入") || trimmed.equals("收入")) return 1;  // 第二个 "收入" 应可能是 "income"
if (trimmed.equals("支出") || trimmed.equals("支出")) return 0;  // 第二个 "支出" 应可能是 "expense"
```

---

### H6. 服务层直接注入 Mapper — 后端

**文件:** `AuthServiceImpl.java:14-15`, `TransactionServiceImpl.java:55`  
**问题:** `AuthServiceImpl` 注入 `AccountBookMapper` 和 `AccountMapper`，直接调用 Mapper 而非通过 `IAccountBookService` / `IAccountService`，违反分层架构约定

---

### H7. 日期解析时区偏移被截断 — 后端

**文件:** `TransactionServiceImpl.java:536-537`  
**影响:** `trans_time` 包含时区偏移（如 `2026-06-15T10:30:00+08:00`）时，`substring(0, 19)` 截断后 `LocalDateTime.parse` 抛异常

---

### H8. 日期解析 UTC 时区偏移导致显示日期错误 — 前端

**文件:** `format.ts:20-28`  
**影响:** 负 UTC 时区用户（美洲等）的日期头显示可能偏移一天

`new Date("2024-01-15")` 按 ECMAScript 规范解析为 UTC 午夜，在 UTC-5 时区 `d.getDate()` 返回 14。

---

### H9. 日期时间戳往返转换导致日期偏移 — 前端

**文件:** `TransactionEditor.vue:268`  
**影响:** 编辑交易时，`new Date(trans_time).getTime()` 在不同 JS 引擎中解析行为不一致（有的按 UTC，有的按本地时间），显示日期可能偏移一天

---

### H10. 同步顺序：先删后推导致 pending-then-deleted 项静默丢失 — 前端

**文件:** `sync.ts:215-218`  
**影响:** 本地创建→本地删除 的交易，pushDeletes 时无 server_id（未推送过），被过滤跳过，但 pushPending 时已被本地移除，最终该删除操作永远不会到达服务器

---

### H11. 后台同步错误被静默吞没 — 前端

**文件:** `sync.ts:115-117, 142-144, 197`  
**影响:** `pushPending`、`pushDeletes`、`pullFromServer` 的 catch 块均为空返回零值。用户无法感知后台同步持续失败，可能数周未备份数据而不知

### H12. 忘记密码页定时器未在卸载时清理 — 前端
