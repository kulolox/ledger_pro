## 2026-06-10 新增：JWT refresh token 双 token 机制

### 变更内容

| 变更 | 说明 |
|------|------|
| JwtUtils 改造 | 抽取 `buildToken()` 公共方法，新增 `generateRefreshToken()` / `validateRefreshToken()`，token 内加 `type` claim (access/refresh) |
| access token | 24h 过期，claim `"type":"access"`，`validateToken()` 排除 refresh 类型 |
| refresh token | 7d 过期，claim `"type":"refresh"`，每次刷新发新 token（滑动过期） |
| AuthController /refresh | 校验 refresh_token → 查用户 → 发新 token 对，直接从 User entity 构建 UserInfoResponse（避免 SecurityContext 未认证） |
| LoginResponse | 新增 `refreshToken` 字段 |
| UserServiceImpl | login/register 同时生成并返回 refresh token |
| 前端 request.ts | catch 块 401 自动刷新：`tryRefreshToken()` → 成功则重试原请求，并发锁 (`refreshPromise`) 防止重复刷新，dev mock token 跳过 |
| 前端 storage.ts | 新增 `getRefreshToken/setRefreshToken/removeRefreshToken`，logout 同步清除 |
| 前端 common.ts | API 返回类型加 `refreshToken: string` |
| 前端 login/register 页 | 登录/注册成功后存储 refreshToken |

### refresh 流程

```
access token 过期 → 后端返回 401 → 前端 catch 块:
  → tryRefreshToken() (原生 uni.request, 避免循环依赖)
  → POST /api/v1/auth/refresh { refresh_token }
  → 成功: 存新 token 对, 重试原请求 (带 _retry 标记防死循环)
  → 失败: 清 tokens, 跳转登录页
```
